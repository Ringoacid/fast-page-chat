# 本文抽出の修正と実サイト検証（2026-09-25）

対象バージョン: 0.9.2

## 変更の目的

画面外にある読み込み済みコメント・画像を引き続き取得しつつ、通常のページ本文モードでは編集欄の下書きを除外し、非表示領域の長い `main` が本来の記事に代わって選ばれる問題を修正した。

- 編集状態は `isContentEditable` で確認する。空属性、`plaintext-only`、継承した編集状態にも対応する。
- 本文候補を選ぶ時点で、祖先・slot・Shadow DOMのホストをたどり、本文取得時の除外条件を適用する。`body` へのフォールバックにも適用する。
- 画像にも編集領域・祖先の確認を適用する。最初の `main` 選択は本文とそろえる一方、本文内の実際に表示される `aria-hidden` 画像は従来どおり取得する。
- ビューポート内だけに制限する判定は追加していない。折り畳み本文の既存の扱いと、明示的に選択した下書きの文章を取得する動作は維持する。

noteの表示件数は61件だが、検証時にDOMへ読み込まれたのは4件だった。残りは「前のコメントを表示」などの操作で追加読み込みが必要であり、この結果を61件すべて取得できたという意味には扱わない。

追加調査した [別のnote記事](https://note.com/quick_pipit5491/n/n7cc68c4d2cdc) は異なるコメントUIであり、「もっとみる」による全文展開の検証は完了していない。[note公式の画像記事](https://note.com/info/n/n87380929f5c9) では画像取得中のDOM更新に伴い本文位置が未設定になる画像があり、全画像の位置まで確認した成功例には含めていない。上表のZenn・noteでは取得した全画像の位置を確認した。

Redditは匿名のテストブラウザでは標準UIが人間確認画面、old UIが403になったため、回避せず未確認として保存した。その後、通常のBraveにある既存の投稿で新旧抽出関数を比較した。Braveでは読み取り専用評価に合わせて時刻・処理時間の計測を定数に置き換えている。本文抽出のロジックは同じだが、拡張機能全体の実行とは区別する。Redditでの画像取得は今回の実ページでは未検証。

これらの自然なページでは、修正対象の下書き混入・非表示 `main` の誤選択が実際に発生していたとは確認していない。実サイト確認は、必要な本文・コメント・画像が修正で失われないことの検証である。混入を防ぐ確認は次のローカル回帰テストで行った。

## 再現した問題と回帰テスト

`scripts/extraction-boundary-check.mjs` はローカルの人工ページを実MV3拡張機能から取得する。17項目すべて成功した。

- 空指定・plaintext-only・継承した編集領域と、その中の非編集子を含む下書きの本文・画像を除外。
- display:none、hidden、aria-hidden、dialog、navigation、編集領域の祖先内にある長いmainを誤選択しない。
- slotを経由する非表示・編集祖先も確認。
- html全体がdisplay:noneのとき、bodyへのフォールバックから本文・画像を取得しない。
- 画面高さ900pxに対し、約7,600px下にある読み込み済みコメント・画像をスクロールせずに保持。
- 折り畳まれたdetails内のコメント本文、明示的な下書きの範囲選択、画像の本文位置を維持。
- 本文内で表示されるaria-hidden画像も取得・位置情報を維持。

保存した旧抽出コードでは11の人工ケースで混入または本文の取り違えを再現し、修正版では解消した。

既存の `node --test test/*.test.mjs` は44件すべて成功。`scripts/browser-check.mjs` も成功し、履歴・画像ON/OFF・本文位置・Redditの遅延画像構造・モデル切替などの既存動作を確認した。モデル応答はモックであり、拡張機能から回答モデルへの実送信は行っていない。

## 再実行と証拠

READMEに記載の `PLAYWRIGHT_MODULE` と必要に応じて `CHROMIUM_BIN` を設定して実行する。

```powershell
node --test test/*.test.mjs
node scripts/extraction-boundary-check.mjs
node scripts/browser-check.mjs
node scripts/zenn-note-content-check.mjs
node scripts/reddit-content-check.mjs
```

実サイトの構造・内容・アクセス制限は変わり得るため、ライブ検証は単体テストと分けて実行する。`.research/release-audit/extract-before.js` はこの作業時の旧版保存であり、存在しなければ新旧比較を省き現行コードを検証する。

最終のZenn・noteスクリプトは、新旧抽出を同じisolated worldの同期処理内で実行し、比較の途中にページの非同期更新が入らないようにしている。この最終版でも両記事のコメント保持・本文一致・画像取得を再実行し、成功を確認した。

- `test-results/extraction-boundary/results.json`: 人工ケース17項目の結果と旧版の再現記録。
- `test-results/zenn-note-content/*-result.json`: 実ページのコメント位置・照合・画像結果。PNGは実ページの表示証拠。
- `test-results/reddit-content/results.json`: 匿名ブラウザのアクセス制限。
- `test-results/reddit-content/brave-readonly-result.json`: 通常Braveでの抽出比較の集計。

## 更新時の扱い

拡張機能を再読み込みし、新しいチャットで取得する。接続サーバーの再起動は不要。保存済みチャットの本文・画像は自動で書き換えない。不要な混入文章を含む過去のチャットは、ユーザーが履歴から削除できる。
