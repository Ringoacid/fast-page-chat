ブラウザ検証はPlaywright 1.62.1を使用したローカル環境で実施しました。配布物に実際のユーザーのブラウザプロファイルや検証中の会話を含めません。検証出力の `test-results/` と調査用の `.research/` はソース配布の対象外です。

ネイティブ接続では、Windowsの実行ファイルと実際のローカル通信を使いました。配布予定の公開鍵と同じIDを持つテスト用拡張を隔離したChromiumプロファイルに読み込み、ランダム名の一時ネイティブホスト登録を使って確認しています。一時登録とインストール先は削除済みです。入力接続を開いたままでも応答とプロセス終了が完了することを確認し、Windowsの通信ハンドル継承と入力EOF待ちによる停止を修正しました。API設定には検証専用の値を使い、OpenAIへ送信していません。

## 未確認または別途必要なこと

- Node.js・Codexが未導入のWindows PCで、Setup.exeから利用者自身のログイン、最初の回答、PC再起動後の利用まで一通り進めること。
- 利用者の実際のChromeで、製品用ホスト登録、権限ダイアログ、ツールバーのactiveTab付与を通した確認。
- 実際のCodex・OpenAI APIへの本文・画像の送信とモデルによる回答。モックの成功からモデルの理解や利用可能性は判断しない。
- 固定IDの配布ZIPによる更新・アンインストールと、異なるIDの旧開発版からの移行時の案内。別IDのIndexedDBを自動移行する機能はない。
- Chrome Web Storeへのデータ申告・申請。今回はGitHub公開までを対象とし、ストア申請は行っていない。

`docs/publication.json` の `policyFinalized` と `storeAssetsVerified` は実装・素材の確認を表します。`cleanInstallVerified` は未確認のためfalseを維持します。`check-release --public` はこの項目が未確認の間は失敗します。`--policy` はポリシーを公開するための確認で、一般公開の全工程の完了を意味しません。

0.9.2でのReddit・Zenn・noteの本文抽出確認は [当時の検証記録](content-extraction-check-2026-09-25.md) を参照してください。今回それらの実サイトをすべて再実行したという意味ではありません。
