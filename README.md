# Fast Page Chat

Chromeのサイドパネルで、現在のWebページを日本語訳・要約・質問できる拡張機能です。Codex App ServerとOpenAI Responses APIを切り替えられます。公開者はRingoacid、ソースコードは[MIT License](LICENSE)です。

**0.10.0はGitHubで配布するベータ版です。Chrome Web Storeには未公開です。** 主な対応環境はWindows x64とデスクトップ版Chromeです。開発・検証の状況と、一般公開に向けて残る確認は[公開前チェックリスト](docs/release-checklist.md)に記載しています。

[配布ファイル](https://github.com/Ringoacid/fast-page-chat/releases) · [不具合の報告](https://github.com/Ringoacid/fast-page-chat/issues) · [プライバシーポリシー](https://ringoacid.github.io/fast-page-chat/privacy.html)

拡張機能を開くと、アクセスを許可されたページのDOMから本文を抽出し、拡張機能内のメモリに準備します。質問時にその本文を直接モデルへ渡すため、「ブラウザを選ぶ→対象タブを探す→本文を取得する」というモデル側のツール呼び出しを省けます。文章の取得自体はローカル処理です。モデルの速度・本文量・回答量による待ち時間は残ります。Geminiより速いことを保証するものではありません。

## Windowsでの導入（GitHubベータ版）

Codexを利用するため、同じPCに接続ヘルパーを一度インストールします。Node.jsとCodexはヘルパーに同梱し、個別の導入、ターミナルでのサーバー起動、接続キーのコピーを省く構成です。CodexへのログインまたはAPI設定は必要です。

1. [Releases](https://github.com/Ringoacid/fast-page-chat/releases)から `FastPageChat-0.10.0-windows-x64-Setup.exe` を取得します。拡張機能も同梱しています。
2. Setup.exeを実行して、このWindowsユーザー用のヘルパーをインストールします。
3. 完了画面の「拡張機能フォルダーを開く」で場所を確認します。Chromeで `chrome://extensions` を開き、「デベロッパーモード」を有効にして、「パッケージ化されていない拡張機能を読み込む」から `%LOCALAPPDATA%\FastPageChat\app\extension` を選びます。
4. 通常のWebページで拡張機能ボタンを押し、初回案内で取得・保存・送信先を確認します。接続ヘルパーへ接続し、Codexでログインするか、APIキーと利用できるAPIモデルを設定します。
5. 参照本文を確認して、最初の質問を送信します。画像は初期状態でOFFです。

ヘルパーは拡張機能からの接続時に起動します。Windowsの自動起動タスクは追加しません。PCの再起動後も、拡張機能を使うときに再接続します。ブラウザの権限確認とCodexのログインは利用者自身が行います。OpenAI APIを使用するとAPI料金がかかります。

初回GitHub版ではChromeへの手動読み込みが必要です。Web Store承認後はストアからの導入に置き換える予定ですが、審査や公開時期は未確定です。

拡張機能を別の場所で管理したい場合は、同じバージョンの `fast-page-chat-0.10.0-extension.zip` を固定フォルダーに展開して読み込むこともできます。使用中のフォルダーは移動・削除しないでください。Windowsインストーラーは未署名です。配布元と添付のSHA256チェックサムを確認してください。

### 更新・アンインストール

0.10.0以降は、同じ公開元の新しいSetup.exeでヘルパーと同梱拡張機能を更新してから、Chrome側で拡張機能を再読み込みします。ZIPを別フォルダーで管理している場合は、その内容も更新します。生成中の会話は停止してから更新してください。ブラウザの拡張機能を削除して入れ直すと履歴を失うため、通常の更新では削除しません。

ヘルパーのアプリは `%LOCALAPPDATA%\FastPageChat\app`、接続設定・認証情報・Codexの診断記録などは `%LOCALAPPDATA%\FastPageChat\data` に保存します。ヘルパーを削除するにはPowerShellで次を実行します。

```powershell
& "$env:LOCALAPPDATA\FastPageChat\app\uninstall.ps1"
```

通常はデータを残します。認証情報とヘルパーの保存データも削除する場合だけ、末尾に `-DeleteData` を付けて実行します。ブラウザ内の履歴・設定は別管理なので、拡張機能の削除またはブラウザのデータ消去も必要です。ローカルの削除によって、OpenAIに送信済みのデータが削除されるわけではありません。

## 開発用の手動セットアップ（Windows）

Node.js 22.9以降が必要です。外部npmパッケージのインストールやビルドは不要です。以下はこのフォルダーで実行します。

### 1. 接続先を準備

**Codexを使う場合**

Codex CLIが利用できる状態で、拡張機能専用の環境に一度ログインします。

```powershell
node --env-file-if-exists=.env scripts/codex-login.mjs
```

普段のCodexと分けた `.local/codex-home` にログインします。普段のスキル・MCP・プロジェクト指示を持ち込まないための構成です。アカウントで利用可能なモデル・利用制限が適用されます。`Codex App Server` はこのサーバーが起動する専用CLIプロセスです。起動中のCodexデスクトップアプリの会話へ接続する機能ではありません。

`codex` が見つからない場合は `.env.example` を `.env` にコピーし、`CODEX_BIN` に `codex.exe` の絶対パスを設定してください。Windowsのパスには `/` も使えます。

**OpenAI APIを使う場合**

`.env.example` を `.env` にコピーし、`OPENAI_API_KEY` と、利用可能なAPIモデルのIDを `OPENAI_MODEL` に設定してください。モデルIDは拡張機能の入力欄にあるモデルメニューから追加・選択できます。APIキーはチャットに貼らず、ローカルの `.env` に保存してください。APIの利用料金がかかります。

### 2. 接続サーバーを起動

```powershell
node --env-file-if-exists=.env server/main.mjs
```

または `start.ps1` を実行します。接続先は `http://127.0.0.1:4318` です。起動したターミナルは使っている間そのままにします。終了は Ctrl+C。自動起動は設定していません。

初回起動で `.local/connection-key.txt` が作られます。この中の文字列を、次の手順で拡張機能に入力します。これはこのPCの接続用キーで、OpenAI APIキーとは別です。

### 3. Chromeに拡張機能を読み込む

1. Chromeで `chrome://extensions` を開き、「デベロッパーモード」を有効にします。
2. 「パッケージ化されていない拡張機能を読み込む」で、このプロジェクトの **extension** フォルダーを選びます。
3. ツールバーに「Fast Page Chat」を固定します。
4. 翻訳したい通常のWebページで拡張機能ボタンを押します。毎回ボタンを押さずに使う場合は、設定の「すべてのWebサイトへのアクセス」で「一度だけ許可する」を押し、ブラウザの確認画面で許可します。
   パネルを閉じるには拡張機能ボタンをもう一度押すか、パネル右上の「×」を押します。
5. 右上の「設定」に `.local/connection-key.txt` の内容を入力し、「保存して接続確認」を押します。
6. 入力欄の左下から接続先とモデルを選択します。
7. 「日本語に翻訳」で定型文を入力し、必要なら編集して送信します。

CodexのモデルメニューはApp Serverから取得した候補を表示します。既定モデルも選べます。APIは利用できるモデルIDを一度追加すると、以降は一覧から選択できます。接続先とモデルはチャットごとに保存されます。

設定の「チャットの名前」で、最初の回答後のAIタイトル生成と、後続の回答後の自動更新を別々に切り替えられます。両方とも初期状態はONです。新規設定では回答と同じ接続先・モデルを使い、設定から独立した接続先とモデルを指定することもできます。既存の明示的なタイトル設定は引き継ぎます。利用可能なモデルはアカウントや接続先によって異なります。タイトル生成に失敗するとチャット名の下に原因と「タイトルを再生成する」ボタンを表示します。回答・履歴・現在の名前は維持され、再生成中も質問を続けられます。失敗通知は履歴を開き直しても残り、再生成に成功すると消えます。再試行はその時点のタイトル生成設定を使い、自動生成をOFFにしていても実行できます。手動で変更した名前は以降自動更新しません。タイトル生成・再生成にはページ名と会話の一部を追加でモデルへ送信するため、OpenAI APIを選んだ場合はAPIの利用料金がかかります。

タイトル生成モデルは設定のプルダウンから選びます。Codex App Serverでは取得したモデル一覧、OpenAI APIではGPT-6の候補と回答用モデルメニューで登録したAPIモデルが表示されます。Codex側の候補は設定の更新ボタンから再取得できます。

### 0.8.0への更新

Braveでは `brave://extensions`、Chromeでは `chrome://extensions` を開き、Fast Page Chatの再読み込みボタンを押します。バージョンが **0.8.0** になったら、パネルをいったん閉じて「F」ボタンで開き直します。接続サーバーの画像枚数と送信サイズのチェックも更新したため、サーバーをCtrl+Cで終了し、`start.ps1` または `node --env-file-if-exists=.env server/main.mjs` で再起動してください。接続キー・既存のモデル設定・0.2.0以降の履歴とスキルは引き継ぎます。設定の「読み込む画像の最大枚数」で1〜600枚を指定できます。初期値は6枚です。増やした分を取り込むには「画像を再取得」を押してください。

0.7.0では画像の最大枚数を1〜24枚から設定できるようにしました。0.8.0ではこれを600枚まで広げています。多い設定では1枚ごとの画像を縮小して送信サイズを抑えます。取得に時間がかかる場合は3分で外部画像の読み込みを止め、取得済みの画像を使います。プレビューは最初の40枚を表示し、「さらに表示」で40枚ずつ追加します。[OpenAIの画像入力仕様](https://developers.openai.com/api/docs/guides/images-vision)では画像トークンも入力枠を使うため、600枚すべてを一度に処理できるかは選択したモデルと画像内容によります。

0.6.1では、Amazonの商品画像のように画面に表示されていても `aria-hidden="true"` が付く画像を取得できるようにしました。本文の参照元を保ったままなら「画像を再取得」で更新できます。ページを再読み込みした場合は、新しいチャットを作成してください。

0.6.0では、毎ページのボタン操作を省きたい場合に設定の「すべてのWebサイトへのアクセス」で「一度だけ許可する」を押せるようにしました。ブラウザの確認画面での許可が必要です。0.5.0では、外部画像の元データを取得するための任意権限を追加しています。画像ON → 枚数ボタン →「外部画像の取得を許可」で、表示された画像配信元へのアクセスだけを許可できます。許可は配信元ごとに保持されます。

0.4.0〜0.6.1および0.8.1への更新は拡張機能の再読み込みだけで利用できます。0.7.0・0.8.0への更新、または0.3.x以前からの更新では、接続サーバーもCtrl+Cで終了し、`start.ps1` または `node --env-file-if-exists=.env server/main.mjs` で再起動してください。

0.3.1ではRedditの「ぼかした背景」と「手前の投稿画像」が同じ画像URLを使う場合の取得失敗を修正しました。取得できなかった背景を重複判定に登録せず、本画像を引き続き取得します。同じ構造と外部画像を使う回帰テストで、修正前の失敗と修正後の取得・切り出しを検証しています。

全サイトへのページアクセスは任意です。有効にすると、パネルを開いている間はアクティブな通常のWebページをタブの切り替えやページ移動に合わせて自動取得できます。ブラウザによる最初の許可確認は省略できません。設定の「全サイトの許可を解除」で一括アクセスを無効にできます。無効のときやページにアクセスできないときは、読みたいページを表示して、**ブラウザ上部のツールバーにある拡張機能の「F」ボタン**をクリックしてください。ブラウザ共通のサイドパネルボタンや、パネル内の「再取得」だけでは一時的なアクセス権が付かない場合があります。

0.5.1では、遅延読み込み指定の小さなトピックアイコンが画像枠を埋めていた問題を修正しました。画像抽出は明示された記事本文領域（Zennの `article .znc`、`itemprop="articleBody"`）を優先します。読み込み方式に関係なく小さな表示画像を除き、未読み込みで寸法不明の画像は引き続き取得します。閉じた折り畳み内の画像は除外します。本文テキストの抽出範囲は変更せず、画像の位置は元のDOMで対応づけます。既存チャットに保存済みの画像は自動では入れ替わらないため、新しいチャットか「画像を再取得」を使ってください。

## 使い方

0.4.0では、画像の位置へ `[画像1]`、`[画像2]` を挿入し、同じ番号の実画像と一緒にCodex/APIへ渡します。本文プレビューでも対応を確認できます。OFFでは追加した番号も送信しません。位置はDOMの読み順に基づき、画面の段組みや座標を表すものではありません。古い履歴、切り詰めた本文の範囲外、位置を特定できない選択範囲では「位置不明」として渡します。

新しいチャットで画像をONにすると、位置情報も取得します。既存画像は元ページで「画像を再取得」する必要があります。保存時から本文や文書が変わっている場合は、誤った段落に結び付けないよう取得を止めるので、新しいチャットで取得してください。

- **テーマ**：右上の設定で「ライト」「ダーク」「システムに合わせる」を選択。選択は保存されます。
- **モデル**：入力欄左下でCodex／APIとモデルを選択。現在のチャットの続きから反映します。
- **エフォート**：入力欄の「エフォート」から選択。Codexはモデル一覧に含まれる対応値を表示し、「自動」は従来通り速度を優先します。APIはモデルごとに対応値が異なり、「自動」なら指定を省略してモデルの既定値を使います。非対応値でエラーになる場合は自動に戻してください。設定はチャットごとに保存し、モデルの変更時は自動に戻します。
- **画像**：入力欄の「画像 OFF / ON」でワンタッチ切り替え。初期値はOFFです。ONにすると画面外を含む本文中の画像を設定した最大枚数まで取得し、枚数ボタンからプレビュー・再取得できます。最大枚数は設定から1〜600枚で変更でき、初期値は6枚です。増やした場合は「画像を再取得」で追加分を読み込みます。減らした場合は保存済み画像を残し、次の送信には先頭から設定枚数だけを使います。過去に画像を使った回答の文章は会話履歴として残り、OFFでは次の送信に画像データを一切含めません。ONに戻すと保存済み画像を再利用します。
- **ページアクセス**：通常は「F」ボタンを押したページへ一時的にアクセスします。設定の「すべてのWebサイトへのアクセス」で「一度だけ許可する」を押し、ブラウザで許可すると、パネルを開いている間はタブ切り替え・ページ移動時に現在のページを自動取得します。「全サイトの許可を解除」で一括アクセスを解除できます。
- **スキル**：入力欄の星形ボタンから定型文を呼び出します。名前と本文を作成・編集・削除でき、削除直後は取り消せます。初期登録は翻訳・要約・わかりやすい説明の3つ。スキルを選ぶと入力欄へ入り、編集してから送信できます。このスキルは定型文であり、CodexのSKILL.mdとは別の機能です。
- **送信**：既定はEnterで送信、Shift+Enterで改行。日本語変換中のEnterでは送信しません。設定でCtrl／⌘+Enter送信にも変更できます。
- **履歴**：左上から過去のチャットを検索・再開できます。本文も検索対象です。ピン留め、名前変更、削除、削除直後の取り消し、Markdownでの書き出しに対応します。
- **新しいチャット**：右上の＋で現在のページについて新しく始めます。既存のチャットは履歴に残ります。
- **参照する本文**：入力欄上部の小さなページボタンから確認。新規チャットではページ本文／選択した文章の切り替えと再取得ができます。長文の切り詰めは「一部を取得」と表示します。
- **停止・再試行**：生成中は送信ボタンが停止ボタンに変わります。途中の回答も履歴に残り、後続の質問には含めません。中断した回答の再試行ボタンは元の質問を入力欄へ戻します。
- **回答**：見出し・箇条書き・太字・コード・リンクなどを表示。回答下部でコピーできます。使用モデルにカーソルを合わせると回答時間を確認できます。

チャットと参照本文はブラウザ内のIndexedDBに保存され、パネルを閉じてもブラウザを再起動しても履歴から再開できます。接続キーと表示設定は拡張機能のローカルストレージに保存します。クラウド同期は行いません。拡張機能の削除やブラウザデータの消去で失われるため、必要な会話は書き出してください。

**各チャットは開始時の本文を保持します。** 別ページへ移動しても会話の参照先は変わりません。過去のチャットでは「保存したページ」と表示します。現在のページについて聞く場合は＋で新しいチャットを作成します。

保存した会話に往復数の上限は設けず、回答時には直近6往復の完了した会話を送ります。生成中は約1.5秒間隔で受信時に中間保存します。突然閉じた場合は最後の保存以降の文章が失われることがあります。保存容量不足などのエラーは明示します。複数パネルからの同時生成をロックし、保存時の版番号比較で古い内容による上書きを防ぎます。

## データの流れと制約

```text
現在のページ → DOM本文抽出 → サイドパネル（質問時にローカル履歴へ保存）
                                  ↓ 質問の送信・タイトル生成時
                         127.0.0.1:4318（接続キー認証）
                           ├─ Codex App Server（stdio JSON-RPC）
                           └─ OpenAI Responses API（SSE）
                                  ↓
                           回答を順次表示
```

- Chrome Manifest V3。既定のページアクセスは `activeTab` による一時的な許可です。設定から任意で全サイトへの永続的なホスト権限を要求できます。初回はブラウザの許可確認が必要で、設定から解除できます。全サイトの許可中は、画像ON時の外部画像も配信元ごとの確認なしで取得できます。全サイトを許可しない場合は、外部画像の元データ取得に必要な配信元を個別に許可できます。ホスト権限はブラウザの仕様上、その配信元のページアクセスにも適用されます。常駐コンテンツスクリプトや巡回処理は追加しません。別途、ローカル接続用に `http://127.0.0.1/*` を許可します。
- 読み込み済みのテキストと本文内の `img` 要素が対象です。PDF・動画フレーム/字幕・CSS背景画像・閉じたShadow DOM・iframeの内部・DOMにまだ追加されていない画像/コメント・全文の自動スクロールには対応していません。画像内の文字は画像対応モデルに読み取らせることができますが、縮小・画質・文字サイズにより読み取れない場合があります。
- 画像は設定した最大枚数（1〜600枚、初期値6枚）までJPEG化します。少ない設定では長辺を最大1,600pxとし、多い設定では画像をさらに縮小します。画像データの合計は最大6,000万文字（Base64で約45MB）なので、画像内容によっては設定枚数に届かない場合があります。表示範囲外の画像も元URLから取得します。通常の `loading="lazy"`、`data-src` / `data-original` / `data-lazy-src` も対象です。ページをスクロールしたり読み込み属性を書き換えたりしません。候補は最大600件、並列8件、1画像の取得は10秒・12MBまで、外部画像の読み込み全体は3分までです。Cookieや接続キーを画像配信元へ送りません。認証が必要な画像や取得拒否の場合は取得できないことがあります。元データを取得できない場合だけ、表示中の画像領域の切り出しへ戻ります。画面全体のスクリーンショットは保存・送信しません。
- 画像ONのときだけ画像データを送信します。OFFでも取得済み画像は履歴内に保持されます。画像は質問ごとに再送され、入力コストが増えます。保存画像の再取得は元のページ・タブ・文書が一致する場合のみ可能です。元ページの再読み込みや移動後は新しいチャットで取得してください。0.2.0の既存チャットに初めて画像を追加する場合も新しいチャットを使います。
- 本文は `main` / `role=main` を優先し、なければ `body` を抽出します。本文候補の親要素も確認し、ナビゲーション、フォーム、編集可能な領域、明示的に非表示にされた領域などを除きます。公開されたShadow DOMも読みます。画面内だけには絞らず、スクロール前でも読み込み済みのコメントを取得します。折り畳み本文はDOMとサイトの表示指定により取得できる場合があります。サイトごとに完璧な抽出を保証するものではないため、送信前に本文を確認できます。
- 1回の取得は最大60,000文字です。超える場合は切り詰めを明示します。長いページの続きは範囲を選んで翻訳してください。モデルの出力上限などで回答が完了しない場合はエラーとして表示します。自動分割翻訳は未実装です。
- モデルへの入力は直近6往復。1つの回答が30,000文字を超える場合、続けるには新しいチャットを作ります。質問ごとに本文と会話を再送するため、長い文書では入力コストが増えます。
- URLのクエリーとフラグメントは送信前に除きます。通常の本文に含まれる個人情報を自動匿名化する機能はありません。
- ページ内の指示は信頼できない資料として扱い、モデルへの指示と区別します。表示には `textContent` を使い、取得本文や回答をHTMLとして実行しません。
- APIは `tools: []` / `tool_choice: "none"` / `store: false`。`store: false` はプロバイダー側のあらゆるログが消えることを保証する設定ではありません。
- Codexは専用ホーム、空の作業フォルダー、一時セッション、read-only、シェル・Web検索の無効化、ページ読解用指示を使います。クライアントはツール実行・承認要求を受け付けません。App Serverの仕様変更・管理者ポリシーによって挙動が変わる場合があります。
- ローカルサーバーは127.0.0.1にのみバインドし、接続キー・Origin・Hostを検証します。APIキーは初回設定画面からPC内のヘルパーへ保存します。保存済みキーの値を診断や設定の応答として拡張機能へ返さず、Webページにも渡しません。Windowsの設定保存ではDPAPIを使用します。本文や回答を接続サーバー独自のログへ書き出しません。
- Codex自身の認証ファイル・診断ログ・内部データが専用ホームへ残る場合があります。一時セッションと標準エラー出力の抑止は、記録が一切残らないことを意味しません。データの取得・送信・保存・削除は[同梱プライバシーポリシー](extension/privacy.html)に記載しています。

## 開発・検証

基本チェック、固定したPlaywright環境、ソース配布の手順は [CONTRIBUTING.md](CONTRIBUTING.md) を参照してください。CIは実モデルへ通信せず、単体テストとallowlist方式のソース梱包検査を実行します。Windowsヘルパーやツールバーの実操作は別途確認が必要です。

0.10.0の実施済みチェックと未確認範囲は[検証記録](docs/validation-0.10.0.md)にまとめています。

本文と画像の対応は、複数段落・Shadow DOMとslot・選択範囲・長文切り詰め・画像OFF・履歴再開・保存本文の変化・API/Codexへの入力内容で検証します。モデルによる理解そのものはモックテストの検証範囲外です。

```powershell
node --test test/*.test.mjs
node --env-file-if-exists=.env scripts/check-codex.mjs
```

自動テストはSSEのUTF-8境界、認証・Origin・Host検証、入力検証、通信切断時のキャンセル、APIへの送信内容、Codex通知の会話分離・中断・終了処理を確認します。モデルのテストはモックで、課金される推論を行いません。

`scripts/browser-check.mjs` はPlaywrightがある開発環境用です。通常利用には不要です。`PLAYWRIGHT_MODULE` にPlaywrightの `index.mjs`、必要なら `CHROMIUM_BIN` にテスト用Chromiumを指定して実行できます。テスト用のローカルページとモデル応答、拡張機能の隔離コピー、空きポートを使用するため通常サーバーは停止せずに実行できます。

画像取得は、取得不可の候補・直接取得できる画像・画面切り出し候補が混在する並び順も検証します。上限6枚で「取得不可1枚 → 直接取得5枚 → 画面切り出し候補1枚 → 直接取得1枚」を置き、採用した6枚の順番・本文中の位置・切り出した画素をブラウザで確認します。自動テストでは、上限到達後の不要な撮影を避けること、複数切り出しでの画像データの共有・解放、サイズ超過時の後続画像採用、ページや画像位置の変化による中止も確認します。

タイトルの失敗通知と再生成は、同じPlaywright環境で `node scripts/title-retry-check.mjs` を実行すると確認できます。失敗通知の永続化、再試行の成功・再失敗、回答の重複防止、次の質問や手動の名前変更との競合を実際の拡張機能画面で検証し、ライト・ダーク・幅320pxの画像を `test-results/title-*.png` に保存します。実モデルへの通信は行いません。

このチェックは実際のMV3拡張機能を隔離プロファイルに読み込みますが、ブラウザのツールバーボタンを押せないためサイドパネルを通常タブで開き、active tab選択だけをテスト用に差し替えます。本文抽出の `chrome.scripting` は実際に動作させます。ユーザープロファイルでのインストール、ツールバーボタン、activeTabの権限付与は手動確認が必要です。

0.5.1では34件の自動テストとChromiumの統合テストを実施。従来の履歴・スキル・テーマ・モデル・抽出テストに加え、エフォートの選択/保存/送信/モデル変更時リセット、画像プレビュー、ON/OFFでの送信データ分離、画像付き履歴の再開、別ページからの混入防止、画像中心のページ、Codex/APIの画像入力形式を検証しています。モデル応答はモックです。外部画像の切り出しテストは実際のページ描画を使いますが、`captureVisibleTab` の戻り値だけテスト用スクリーンショットに差し替えます。ツールバーボタンからのactiveTab権限付与と実際のモデルによる画像認識は手動確認が必要です。

0.6.0では、全サイトへの任意アクセスを要求する設定ボタンの要求範囲と、許可を拒否した場合の表示もChromiumの統合テストで確認しています。ブラウザ標準の許可確認画面での承認と、承認後の別サイト取得は手動確認が必要です。

画像とエフォートの接続仕様は [Codex App Server](https://learn.chatgpt.com/docs/app-server)、[Responses APIの画像入力](https://developers.openai.com/api/docs/guides/images-vision)、[Reasoning effort](https://developers.openai.com/api/docs/guides/reasoning) を参照しています。
